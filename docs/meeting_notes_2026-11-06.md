> 그림 생략: train.csv 기준 · LightGBM, 변이 유무와 변이 수 특성, 층화 5겹 교차 검증

**우리가 할 수 있는 것**

- **겹치는 아형:** 2단계 분류와 예측 규칙을 비교해 Macro F1이 오르는 방식을 고릅니다.
- **소수 아형:** 클래스 가중치와 결정 기준을 시험하고, 아형별 F1을 함께 기록합니다.
- **변이 정보:** 변이 수, 변이 유형, 주요 변이 자리, 논문 기반 경로 특성을 하나씩 추가합니다.
- **오답 분석:** 혼동이 큰 아형 쌍을 찾아 구분에 도움이 되는 유전자를 확인합니다.
- **서비스 설계:** 애매한 사례를 표시하고, 경량 모델과 성능 모델을 함께 쓰는 판독 흐름을 제안합니다.

- **차별화:** 성능 모델과 경량 모델을 비교하고, 의료진 보조 시나리오를 제시합니다.
- **안전장치:** 공통 교차 검증, 폴드 내부 전처리, 재현성 점검을 지킵니다.

### T-2. 연구 가설

대표 연구 가설은 유전자 변이 프로필이 같은데 라벨이 다른 아형을 2단계로 분리하면, 단일 다중 분류보다 전체 Macro F1이 향상된다는 것입니다. 모든 가설은 실험 전에 예상 결과를 적고 같은 폴드에서 검증합니다.

| 번호 | 연구 가설 | 근거 | 검증 방법 | 지지 기준 |
| --- | --- | --- | --- | --- |
| 1 | 겹치는 아형을 2단계로 분류하면 전체 Macro F1이 오른다 | 같은 변이 프로필이 KIPAN·KIRC 273쌍, GBMLGG·LGG 174쌍 | 단일 분류와 2단계 분류 비교 | Macro F1 평균 상승, 폴드별 안정성 유지 |
| 2 | 변이 자리 특성은 일부 아형의 분류를 개선한다 | BRAF V600E가 THCA·SKCM에 집중 | 변이 유무 특성과 변이 자리 특성 비교 | 대상 아형의 F1 상승 |
| 3 | 변이 유형 정보를 나누면 성능이 오른다 | 침묵 변이 제외 시 0.366에서 0.349로 하락 | 전체 변이 수, 유형별 변이 수, 유전자별 유형 특성 비교 | Macro F1 평균 상승 |
| 4 | 전체 변이 부담은 일부 아형을 구분하는 독립적 단서다 | 변이 수 중앙값 THYM 2개, SKCM 85.5개 | 변이 수 특성 추가 전후 비교 | 소수 아형 포함 Macro F1 상승 |
| 5 | 논문 기반 드라이버·경로 특성은 소수 아형 성능을 높인다 | 많은 유전자의 변이가 드물게 나타남 | 유전자 특성 대비 경로 특성 추가 효과 비교 | 소수 아형 평균 F1 상승 |
| 6 | 유전자를 크게 줄인 경량 모델도 성능 손실을 작게 유지한다 | 일부 표지 유전자의 신호가 강함 | 유전자 수별 성능, 크기, 추론 시간 측정 | 손실 대비 비용 감소 |

**회의에서 합의할 기준 예시:** 폴드 평균 Macro F1이 공통 기준보다 0.01 이상 오르고, 폴드 절반 이상에서 개선되면 가설을 지지합니다.

### A-2. 모델 전략

먼저 겹치는 아형과 변이 특성을 개선하고, 안정적인 후보만 앙상블합니다.

1. **공통 검증:** 층화 그룹 5겹 기준을 확정합니다.
2. **기본 특성:** 유전자별 변이 유무와 환자별 변이 수를 준비합니다.
3. **고급 특성:** 변이 유형, 주요 변이 자리, 논문 기반 드라이버·경로 특성을 시험합니다.
4. **겹치는 아형 전략:** 24개 묶음 분류 후 세부 아형을 판단하는 2단계 분류를 시험합니다.
5. **모델 비교:** 선형 모델과 트리 모델의 성능과 오답 패턴을 비교합니다.
6. **앙상블:** 공통 교차 검증에서 성능이 좋고 오답 패턴이 다른 모델만 묶습니다.
7. **경량 모델:** 점수 손실, 파일 크기, 메모리, 추론 시간을 비교합니다.
8. **서비스 시나리오:** 입력, 출력, 낮은 확신도 처리, 의료진 검토 흐름을 설명합니다.

### A-6. 실격 방지와 제출 전 점검표

Data Leakage가 확인되면 리더보드 1위여도 실격될 수 있으므로, 점수 개선보다 규칙 준수를 먼저 확인합니다.

| 위험 사항 | 불이익 | 팀 예방 규칙 |
| --- | --- | --- |
| Data Leakage | 실격, 수상 제외 | Test는 추론에만 사용 |
| 다른 사람 코드·과거 대회 코드 사용 | 제출 무효, 평가·시상 제외 | 이번 대회용 코드로 새로 작성 |
| 동일 주제 타 대회 코드와 90% 이상 유사 | 순위 제외 | 전처리·파생변수·모델 설정을 직접 설계하고 기록 |
| 재현 불가 코드 | 수상 제외 가능 | 시드와 버전 고정, 12일 전체 재실행 |
| 중복 계정·과거 대회 페이지 제출 | 실격 또는 공식 제출 미인정 | 현재 대회 페이지와 개인 계정 1개만 사용 |

**Data Leakage 방지 원칙**

| 작업 | 안전한 방법 | 금지할 방법 |
| --- | --- | --- |
| 변이 유무·유형 특성 | 각 행 안에서 계산 | 전체 데이터 통계로 기준 설정 |
| 변이 자리 사전 | 학습 폴드에서 생성, Valid와 Test에는 그대로 적용 | Train과 Test를 합쳐 생성 |
| 특성 선택·군집화 | 학습 폴드 안에서 기준 생성 | 전체 데이터로 수행 |
| 스케일링·결측치 처리 | 폴드마다 학습 폴드로 재학습 | 폴드 분할 전 fit |
| 처음 보는 값 | 0 또는 미등록 규칙 적용 | Test에 맞춰 컬럼 추가 |
| 2단계 분류·앙상블 | 학습 폴드와 OOF 예측으로 규칙 결정 | Test 예측을 보고 수정 |
| Test 정보 | 예측에만 사용 | EDA, 행 수, 인덱스 활용 |

**최종 제출 전 점검**

- [ ] Test로 인코더, 스케일러, 결측치 보간, 특성 선택을 fit하지 않음
- [ ] Test에서 EDA를 하거나 행 수, 인덱스를 전처리·학습에 쓰지 않음
- [ ] 다른 사람이 작성한 코드나 Test 데이터를 구현에 사용하지 않음
- [ ] 전체 과정을 주석과 함께 한 파일로 정리하고 UTF-8로 저장함
- [ ] 코드에 `/data` 입출력 경로, 시드, 하이퍼파라미터, 운영체제, 라이브러리 버전을 적음
- [ ] 라이브러리 로딩부터 추론까지 오류 없이 재실행함
- [ ] 추론용 모델 파일 링크 또는 메일 첨부를 준비함
- [ ] 사전학습 모델을 썼다면 논문 링크와 출처를 적음
- [ ] 공개 코드나 과거 대회 코드를 기반으로 하지 않음

**최종 누수 교차 점검**

- [ ] `concat(train, test)` 뒤 fit 하는 코드가 없음
- [ ] Test에 `fit`, `fit_transform`, `get_dummies`, `align`을 쓰지 않음
- [ ] 전처리기와 특성 기준을 폴드 안에서 다시 학습함
- [ ] 구현 담당자 외 1명이 최종 코드를 재확인함

### A-7. Git 협업 규칙

`main`에는 직접 push하지 않고, 작업 브랜치와 PR로만 병합합니다.

1. 최신 `main`을 받습니다.
2. `feature/작업내용` 브랜치를 만듭니다.
3. 코드 작업 후 커밋합니다. 예: `feat: 변이 유형별 개수 특성 추가`
4. 브랜치를 push하고 PR을 생성합니다.
5. 팀원 확인 후 `main`에 병합합니다.

- [ ] 저장소 생성과 초기 파일 등록
- [ ] 팀원별 커밋 템플릿 설정
- [ ] README와 실험 기록 담당자 지정
- [ ] 데이터와 모델 파일이 제외되는지 확인
- [ ] 최종 코드를 한 파일로 정리할 담당자 지정

**Git 유의사항**

- `data/`, 모델 파일, `.env`는 저장소에 올리지 않습니다.
- 커밋 전 `git status`로 올라갈 파일을 확인합니다.
- 공개 코드, 과거 제출 코드, 타 대회 코드를 기반으로 작성하지 않습니다.
- 시드, 파라미터, 라이브러리 버전을 코드에 기록합니다.
- PR에서 Data Leakage 점검 항목을 확인한 뒤 병합합니다.
