### 4-2. 11/9: 쌍 규칙 발견

**발견**: 교차 검증과 리더보드 차이의 원인은 코드 실수가 아니라 **쌍 규칙 유무**였다.

**오후: 고변이 대응 (팀원 v9 → v14)**

|---|---|---|---|
| v9 | 변이 수 보정 LR 65% + LightGBM 20% + 암종별 변이 빈도 15% | 0.52017 | 0.51497 |
| 스태킹 15% | v9 85% + 2단 LightGBM 15% (내부 4겹 예측을 입력으로) | 0.52999 | 0.52455 |

- 스태킹은 쌍 규칙 없이도 v9보다 +0.0198 높았다(0.44399 → 0.46376). 모델 자체 실력이 오른 것이다.

**저녁: 아미노산 치환 서명 (v21)**

- 아이디어: 어떤 유전자가 변했는지가 아니라 **무엇이 변이를 만들었는지**를 본다.

| 변이를 만든 원인 | 남기는 흔적 | 관련 아형 |
|---|---|---|
| 자외선 | C>T 치환 | SKCM |
| 흡연 | C>A 치환 | LUSC, LUAD |
| APOBEC 효소 | C>T, C>G 치환 | CESC, BLCA, BRCA, HNSC |
| 복제 오류 교정 결함 (MSI) | 반복 자리 frameshift | COAD, STES, UCEC |

- 방법: 환자마다 아미노산 치환 쌍(R→C, G→V 등) 비율, 종결·frameshift 비율, 변이 수를 계산해 LightGBM으로 학습했다. 환자 한 명 안에서만 계산하므로 정답이 새지 않는다.

- 근거: Alexandrov 외 (Nature 2013, 2020), TumorTracer (BMC Med Genomics 2015), Jiao 외 (Nature Communications 2020), OncoNPC (Nature Medicine 2023)

## 7. 최종 모델 (강화 코돈 20% + 치환 원형 LDA 5%)

| 단계 | 내용 |
|---|---|
| 1. 표기 정리 | HGVS 파서, 반복 표기 정리, 희귀 유형 제외 (기준은 학습 데이터로만) |
| 2. 피처 | 유전자별 변이 여부, 절단형 변이, 핫스팟(`유전자_위치_영향`), 위치 구간, 변이 수 집계 15개, 동의 변이, 정확한 미스센스 |
| 3. 기본 모델 | LR(변이 수 보정, 변이 수 구간 LR 30% 포함) 65% + LightGBM(시드 5개 평균) 20% + 암종별 변이 빈도 15% |
| 4. 스태킹 | 기본 모델 예측과 변이 수를 입력으로 받는 2단 LightGBM 20% |
| 5. 치환 서명 | 아미노산 치환 서명 LightGBM 20% (여기까지 v21) |
| 6. 강화 코돈 후보 | 코돈 역추정 치환 LightGBM(시드 5개) + 강화 서명 LR + 학습형 혼합기 (4-6절) |
| 7. 1차 혼합 | 쌍 규칙 적용 전 로그 점수를 v21 80% : 강화 코돈 20%로 합산 |
| 8. 치환 원형 LDA | 1차 혼합 95% + 치환 원형 LDA 5% (4-6절) |
| 9. 후처리 | 쌍 규칙 (KIPAN·KIRC, GBMLGG·LGG) |

| 지표 | 값 |
|---|---|
| 교차 검증 (층화 5겹, 쌍 규칙 적용) | 시드 123 0.5791 · 시드 42 0.5667 |
| 리더보드 | **0.48396** |
| 재현 | 단일 노트북 `cancer_submission_6조 gene-ius 최종코드.ipynb`를 처음부터 실행하면 제출 파일과 2,546행 모두 일치 |

- 모든 기준(어휘, 스케일러, 열 선택)은 학습 데이터로만 만들고, 제출 데이터에는 적용만 했다.

## 10. 배운 점

1. **데이터 구조를 이해한 만큼 점수가 올랐다.** 쌍 규칙, 표기 정규화, 고변이 대응, 돌연변이 서명 모두 모델이 아니라 데이터를 들여다봐서 찾았다.
2. **같은 피처로 모델 종류만 바꾸면 효과가 없었다.** SVM, 나이브 베이즈, 전문가 모델, 설정 조정은 모두 ±0.01 안이었다.
3. **새로운 정보를 넣을 때 가장 크게 올랐다.** 돌연변이 서명은 도메인 지식이 곧 피처가 된 사례다.
4. **쏠림이 보인다고 모두 오류는 아니다.** SKCM 예측을 줄였더니 리더보드가 떨어졌다.
5. **교차 검증은 방향을 알려 주지만 크기를 보장하지 않는다.** 두 시드 원칙도 학습 데이터 안의 과적합은 막지 못했다. 제출 기회를 검증 수단으로 아껴 써야 한다.
6. **기존 모델을 대체하지 말고 조금씩 얹었다.** 강화 코돈 후보는 단독으로는 그대로였지만 20%만 섞자 +0.0044, 원형 LDA는 5%만 섞어 +0.0034였다. 다만 바꾸는 행 수보다 **어떤 근거로 바꾸느냐**가 중요했다(233행을 바꾼 원형 LDA는 상승).
7. **검증 데이터를 제출 데이터처럼 만들 수 있다.** 변이를 솎아낸 검증으로 고변이 구간의 실력을 따로 잴 수 있었다.
8. **실험 원칙은 실패에서 나왔다.** 한 번에 하나만 바꾸기, 폴드 안에서 선택하기, 두 시드 확인하기는 모두 실패한 제출을 분석하며 생긴 규칙이다.
