## 3. 오늘 시도한 방법

### 3-1. v10 (팀 기준 모델, 리더보드 0.4206)

| 변화 | 내용 | 노린 효과 |
|---|---|---|
| 블렌드 | 로지스틱 회귀 0.8 + LightGBM 0.2, 로그 확률 가중 평균 | 두 모델이 함께 동의하는 아형 선택 |
| 표기 정규화 | 종결 코돈 표기 통일(`R213X` → `R213*`), 한 칸 안의 중복 변이 정리, 빈 칸은 변이 없음 | 같은 변이를 같은 피처로 인식 |
| 칸 단위 집계 | (환자, 유전자, 변이 유형)이 같으면 한 번만 셈 | 한 칸에 여러 번 적힌 변이 때문에 변이 수가 부풀지 않게 함 |
| 고변이 대비 학습 | 가짜 배경 변이를 원래 변이 수의 0~2배 추가한 복제본을 비중 0.25로 함께 학습 | 변이가 많은 환자에서도 핵심 신호에 집중 |
| 쌍 규칙 강화 | 행 전체 일치가 없으면, 변이 유전자 3개 이상인 경우 유전자 조합 일치로 비교 | 같은 환자를 더 안정적으로 찾음 |
| 위치 구간 토큰 | 아미노산 위치를 25칸 단위로 묶은 `유전자_구간` 토큰 | 가까운 위치 변이의 비슷한 영향 반영 |
| 가중치 | 핫스팟 ×2, 집계 블록 ×0.5 | 특이도 높은 신호 강조, 변이 수 차이에 덜 흔들림 |

### 3-2. v3 (리더보드 0.3985)

| 변화 | 내용 |
|---|---|
| HGVS 파서 | HGVS 단백질 표기 규칙(Hart et al., 2024)에 따라 변이를 frameshift, extension, delins, insertion, duplication, deletion, substitution으로 먼저 나누고 단백질 영향(synonymous, missense, nonsense, frameshift, inframe_indel)으로 분류 |
| TMB 정의 | 변이 개수 대신 **변이가 있는 유전자 수**로 셈 |
| 핫스팟 어휘 | 등장 횟수가 아니라 등장한 **환자 수** 기준 5명 이상 |
| 앙상블 | 로지스틱 회귀 0.7 + ComplementNB 0.3 (교차 검증 0.4925 → 0.5043) |
| 클래스별 보정값 | 교차 검증에서 쌍 규칙 없이 0.4265 → 0.4354. 최종 제출에는 미사용 |

### 3-3. 도메인 피처 압축 + UMAP + 3자 앙상블 (미제출, 교차 검증 기준)

유전자 4,384개를 도메인 지식으로 128~158개 피처로 압축하고 트리 모델 3개로 앙상블한 접근이다. 리더보드 제출은 하지 않았다.

| 단계 | 내용 | OOF Macro F1 (쌍 규칙 없음) |
|---|---|---|
| 1 | 핵심 유전자 100개(상호정보량 + TCGA 공식 드라이버 가산점) + 염색체 슬롯 24개, LightGBM | 0.3242 |
| 2 | Optuna 하이퍼파라미터 탐색 | 0.3366 |
| 3 | 환자 단위 통계 4개 추가 (총 변이 수, 변이 염색체 수, 드라이버 변이 수·비율) | 0.3384 |
| 4 | LightGBM + CatBoost + ExtraTrees 블렌딩, 클래스별 가중치 사후 최적화 | 0.3493 |
| 5 | 나머지 유전자를 UMAP으로 30차원 압축해 추가 (LightGBM 단독) | 0.3522 |
| 6 | UMAP 158피처 + 3자 앙상블 + 사후 최적화 | 0.3554 |

- **확인한 것**: 환자 단위 통계(총 변이 수, 변이 염색체 수)가 피처 중요도 1·2위였다. 유전자 수 집계가 도움이 된다는 3-5절 결과와 같은 방향이다. 2단계 계층 분류는 0.3439로 오히려 떨어졌다.
- **한계**: 같은 조건(쌍 규칙 없음)에서 v10 계열은 약 0.44다. 유전자를 128개로 압축하면 정보 손실이 커서, 희소 행렬로 전체 유전자를 쓰는 방식이 더 강했다.
- **보완할 점**: 핵심 유전자 선택, 블렌딩 비율, 클래스 가중치를 학습 데이터 전체(또는 전체 OOF)로 정하고 같은 데이터로 채점했다. 그래서 OOF 점수가 실제보다 높게 나왔을 수 있다. 선택과 보정도 폴드 안에서 해야 한다.
- **팀에 가져올 것**: UMAP 임베딩과 변이 염색체 수를 v10에 추가 피처로 붙이는 실험 (폴드 안에서 UMAP 학습)

### 3-4. 표기 처리 실험 (exp18, exp14)

- **exp18**: 종결 코돈 표기만 통일했다. 효과는 +0.0005로 거의 없었다.
- **exp14**: 한 칸에 같은 변화가 위치만 바꿔 반복된 칸을 "변이 없음"으로 지웠다. −0.024로 크게 떨어졌다.
- **해석**: 반복 표기 칸에도 진짜 정보가 있다. 지우면 그 유전자의 변이 정보가 사라지고, 그대로 세면 변이 수가 부푼다. v10의 칸 단위 집계는 유전자 정보는 살리고 개수만 바로잡아 이 문제를 풀었다.

### 3-5. 교차 검증 탐색 (제출 없이)

판정 기준은 쌍 규칙 포함 점수로 **+0.01 이상, 5개 폴드 중 4개 이상 상승**이다.

| 묶음 | 비교한 것 | 결과 |
|---|---|---|
| 모델 설정 (9개) | 앙상블 비중 0.6~1.0, 규제 C 0.1·0.2, LightGBM 강화, 아형별 확률 보정 | 모두 기준과 ±0.0005 안. 확률 보정(검증 절반으로 추정)은 −0.031 |
| 전처리 1차 (8개) | 핫스팟 ×1·×3, 최소 환자 3·10명, 위치 피처, 집계 제거, 침묵 변이 추가 | 위치 피처 +0.0017이 최고. **집계를 빼면 −0.052** |
| 전처리 2차 (7개) | 중복 제거, 위치 피처, 유전자 × 변이 유형, 유전자 수 집계, 조합 | **유전자 수 집계 +0.0035 (4/5 폴드)**가 최고. 유전자 × 유형은 열이 9,905개로 늘어 −0.008 |
| v10 + 유전자 수 집계 | 변이 유전자 수, 절단형 변이 유전자 수, 여러 변이가 있는 유전자 수 | **+0.0023 (5/5 폴드)** |
| v10 고변이 대비 강도 (6개) | 복제 비중 0·0.25·0.5·1.0, 최대 배수 3·5, 집계 ×0.5·×0.25 | v10 기본값(0.25, 3배, ×0.5)이 일반 검증과 고변이 환자 검증 모두에서 최고 |

**위치 피처의 암종별 효과**: UCEC(+0.035), PRAD·LUAD(+0.013), SKCM(+0.012)에서 이득이 있었다. SARC(−0.021), PAAD(−0.018), HNSC(−0.014)에서는 손해였다. 같은 위치의 다른 변이(IDH1 R132H/R132C)를 묶어도 뇌종양(LGG −0.007, GBMLGG −0.001) 영향은 거의 없었다.

## 4. 개선점과 배운 것

### 4-1. 잘된 점

- **입력 처리 개선이 가장 효과가 컸다.** 칸 단위 집계, 표기 정규화, 고변이 대비 학습처럼 입력을 안정적으로 다루는 변화가 모델 교체보다 큰 상승을 만들었다.
- **실패한 제출도 방향을 알려 줬다.** exp14(−0.024)로 "반복 표기 칸을 지우면 안 된다"를 확인했고, v10이 이를 해결했다.
- **도메인 지식이 피처 설계에 들어갔다.** HGVS 표기 규칙, 코호트 구조(KIPAN⊃KIRC, GBMLGG⊃LGG), 핫스팟 생물학, TCGA 공식 드라이버 유전자, 염색체 위치가 모두 모델에 반영됐다.
- **서로 다른 접근을 동시에 시도했다.** 희소 행렬 + 선형 모델(v10, v3)과 압축 피처 + 트리 앙상블 + UMAP을 함께 비교해, 이 데이터에서는 전체 유전자를 쓰는 희소 방식이 더 강하다는 것을 확인했다.

### 4-2. 개선할 점

- **교차 검증 상승이 리더보드로 잘 옮겨지지 않는다.** exp10은 교차 검증 +0.012, 리더보드 +0.0004였다. 교차 검증만으로 제출 후보를 고르지 않는다.
- **검증 방식을 통일해야 한다.** 같은 v10을 두고 팀원 측정은 0.5121, 폴드 안에서 증강·어휘·쌍 규칙 사전을 모두 다시 만든 측정은 0.5042였다. 발표 자료의 수치는 한 가지 방식으로 맞춘다.
- **선택·보정 단계도 폴드 안에서 한다.** 피처 선택, 블렌딩 비율, 클래스 가중치를 전체 데이터로 정하고 같은 데이터로 채점하면 점수가 부풀어 보인다.
- **가상 검증은 방향만 참고한다.** 학습 데이터에 인위적인 변형을 넣은 검증은 효과의 크기를 크게 부풀렸다(예: 표기 통일 예상 +0.016, 실제 +0.0005).
- **제출 횟수는 팀 합산 하루 4회다.** 제출 전에 단톡방에 "몇 번째, 무엇"을 남긴다.

## 5. 서비스 기획 (추천안)

**원발부위 불명암 진단 보조**를 중심에 두고, 표적치료 안내와 설명 리포트를 붙인다.

1. 입력: 환자의 유전자 변이 목록 업로드
2. 입력 검사: 형식이 다르거나 비어 있는 값 자동 확인
3. 예측: 암종 상위 3개와 확률
4. 근거: 판단에 크게 작용한 변이 5개 (예: IDH1 R132H → 뇌종양 쪽 근거)
5. 치료 연결: 표적치료가 있는 변이 표시 (예: BRAF V600E)
6. 주의 표시: 확률이 낮거나 상위 두 아형이 비슷하면 "추가 검사 권장"

한계: 진단을 대신하지 않는 보조 도구이며, 실제 사용에는 의료기기 소프트웨어 인허가와 다기관 데이터 검증이 필요하다.
