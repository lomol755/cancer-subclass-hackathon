## 3. 오늘 시도한 방법

### 3-1. v13: 표기 정규화 보강 (리더보드 0.4323)

모델, 학습 방식, 쌍 규칙은 v10과 같다. 칸 하나 안에서 표기를 train 형태로 맞추는 정규화만 세 가지 추가했다. 모든 기준(사전, 유형별 개수)은 train으로만 만든다.

| 처리 | 예 | 이유 |
|---|---|---|
| frameshift 통일 | `S221Kfs` → `S221fs` | train의 frameshift 표기도 `K16fs`, `-12fs`, `*33fs` 등 여러 형태라 위치만 남겨 통일 |
| 희귀 유형 제외 | 삽입·결실(`del`, `ins`, `dup`) | train 변이 약 25만 5천 개 중 삽입·결실은 3건, splice는 0건. 학습된 적 없는 유형이다 |
| 반복 표기 정리 | `K392E K324E K303E` → train에 나온 표기만 | 같은 변이를 여러 전사체 기준으로 적은 것. train에도 380칸 있다 |

**희귀 유형을 뺀 이유**

- '삽입·결실 개수' 집계 피처는 train 표준편차가 0.015로 매우 작다. 그래서 1개만 있어도 표준화 값이 45배로 튀고, 예측이 근거 없이 SKCM 쪽으로 밀렸다.
- 기존 규칙 "train에서 5명 미만에게만 나온 피처는 버린다"를 변이 유형에도 똑같이 적용했다.

**반복 표기 정리 방법**

- 한 칸에서 위치 숫자만 다른 같은 변화가 3개 이상이면 반복 묶음으로 본다.
- train에 한 번이라도 나온 `유전자_토큰` 표기만 남기고, 하나도 없으면 하나만 남긴다.
- 유전자에 변이가 있다는 사실은 유지하고 가짜 위치 정보만 걸러 낸다.

| 항목 | 값 |
|---|---|
| 교차 검증 Macro F1 (쌍 규칙 포함, 시드 7 / 42 / 123) | 0.5023 / 0.5053 / 0.5039 |
| v10 교차 검증 | 약 0.508 (거의 같음) |
| 제출 예측 변경 | 148행 |
| 리더보드 | 0.4206 → **0.4323 (+0.0117)** |

### 3-2. final v6: HGVS 파서 기반 피처 (리더보드 0.4458, 팀 최고)

오늘 마지막 제출이다. v10의 큰 틀(LR + LightGBM 로그 블렌드, 고변이 대비 증강, 쌍 규칙)은 유지했다. 대신 **변이를 읽는 방식**을 HGVS 표기 규칙(`docs/hgvs_notation_rules.md`) 기반 파서로 바꿨다.

**v10과 다른 점**

| 항목 | v10 | final v6 |
|---|---|---|
| 변이 판독 | 정규식 7종 분류 | HGVS 파서: 표기 통일 → 유형 판정 → 단백질 영향 분류 |
| 표기 통일 | `X` → `*` | `p.` 접두사, 3글자 아미노산(`Arg132His`), `L42=`, `fsX12`, `P233delP` 등도 통일 |
| 핫스팟 키 | `유전자_원래표기` (예: `IDH1_R132H`) | **`유전자_위치_영향`** (예: `IDH1_132_mis`) |
| 집계 피처 | 17개 | 15개 (영향 기준 개수, 변이 유전자 수, 비율 3개, 변이 0개 표시 등) |
| LightGBM | 시드 1개 | **시드 5개 평균** (123~127) |
| 블렌드 비중 | LR 0.8 + LightGBM 0.2 | 5겹 교차 검증 격자 탐색으로 다시 골랐고, 결과도 0.8 + 0.2 |

**핫스팟 키를 '위치 + 영향'으로 바꾼 이유**

- 같은 frameshift가 `K16fs`, `K16Rfs*12`처럼 다르게 적혀 있어도 같은 키(`유전자_16_trunc`)가 된다.
- 표기 방식이 달라도 같은 변이를 같은 피처로 읽게 되고, 핫스팟 정보가 사라지지 않는다.
- 파서는 train 변이 255,164개를 하나도 빠짐없이 읽었다(못 읽은 변이 0개).

**교차 검증 (5겹, 시드 123)**

| 모델 | 쌍 규칙 없음 | 쌍 규칙 적용 |
|---|---|---|
| LR 단독 | 0.4263 | 0.4937 |
| LightGBM 단독 | 0.4162 | 0.4828 |
| **LR 0.8 + LightGBM 0.2** | **0.4406** | **0.5078** |
| LR 0.7 + LightGBM 0.3 | 0.4384 | 0.5053 |
| LR 0.5 + LightGBM 0.5 | 0.4358 | 0.5025 |

- 쌍 규칙은 제출 예측 2,546개 중 210개를 바꿨다.
- 리더보드는 0.4323에서 **0.4458(+0.0135)**로 올랐다. v13처럼 교차 검증보다 리더보드 개선 폭이 크다.

**아직 낮은 아형 (쌍 규칙 적용 F1, 낮은 순)**

| 아형 | F1 | 원인 (EDA) |
|---|---|---|
| PAAD (췌장암) | 0.216 | 핵심 유전자 KRAS, SMAD4 열이 데이터에 없음. OV와 자주 혼동 |
| SARC (육종) | 0.269 | |
| CESC (자궁경부암) | 0.297 | |
| THYM (흉선종) | 0.297 | 핵심 유전자 GTF2I 열 없음. 35%가 아미노산 변화 변이 0개라 THCA·LAML·PRAD와 혼동 |
| PRAD (전립선암) | 0.339 | |

이 아형들은 모델 문제라기보다 **데이터에 핵심 유전자가 없는 한계**다. 발표에서 한계로 설명한다.

### 3-3. 블렌드 비중 비교 (그룹 3겹 검증, 쌍 규칙 없음)

같은 변이 프로필을 가진 환자를 한 폴드에 묶어서 검증했다. 그래야 같은 프로필이 학습과 검증 양쪽에 동시에 들어가지 않는다.

| 후보 | 시드 42 | 시드 123 |
|---|---|---|
| v10 (LR 80% + LightGBM 20% 로그 블렌드) | 0.44755 | 0.45458 |
| **LR 65% + LightGBM 35% 로그 블렌드** | **0.44931** | **0.45504** |
| 원본으로 피처 학습, 증강 유지 | 0.44408 | 미실행 |
| 원본으로 피처 학습, 증강 제거 | 0.44500 | 미실행 |
| LightGBM 10% | 0.44162 | 미실행 |
| LR 단독 | 0.43433 | 미실행 |

- 그룹 3겹 검증에서는 35%가 두 시드 모두 앞섰다(각각 3폴드 중 2폴드 개선).
- 반면 final v6의 5겹 검증에서는 20%가 최고였고, 35%에 가까운 30%는 0.0025 낮았다.
- 차이가 0.002 안팎이라 **검증 방식에 따라 순위가 바뀌는 수준**이다. 비중보다는 표기 처리가 더 큰 영향을 준다.

**쌍 규칙 범위 확인 (일반 층화 검증)**

- 완전 일치 쌍 규칙을 적용하면 Macro F1이 0.43284에서 0.49030으로 오른다.
- 유전자 조합 일치를 더해도 추가로 바뀐 예측은 0개였다. 완전 일치 규칙만으로 효과가 거의 다 나온다는 뜻이다.

### 3-4. 서비스 기획: 원발 내비

원발 부위 불명암(CUP) 환자의 유전자 패널 결과로 가능성 높은 암 아형 후보 3개와 근거를 보여 주는 **진단 보조** 서비스다. 최종 판단은 의료진이 한다.

**기획 근거 (논문)**

| 근거 | 내용 |
|---|---|
| ESMO 가이드라인 (Krämer 등, 2023) | 전체 암의 3~5%가 원발 부위 불명암 |
| OncoNPC (Moon 등, Nature Medicine 2023) | 유전체 예측과 일치하는 치료를 받은 환자의 사망 위험비 0.35 |
| CUPISCO (Krämer 등, Lancet 2024) | 분자 맞춤 치료의 무진행 생존 중앙값 6.1개월 대 기존 항암 4.4개월 |
| Jiao 등 (Nature Communications 2020) | 상위 3개 정확도가 1개보다 크게 높음 → 후보 3개 표시 근거 |
| Hoadley 등 (Cell 2018) | 분자 분류의 주된 축은 기원 세포와 조직 → 계열 묶음 안내 근거 |

**웹 화면 (`wonbal_navi_app.html`, 단일 파일, 인터넷 없이 작동)**

| 기능 | 내용 |
|---|---|
| 변이 입력 | 직접 입력 또는 CSV·TSV 파일. `p.` 접두사, `X` 종결 표기 허용 |
| 표기 정리 | `X`를 `*`로 통일, 중복 제거, 학습에 없는 유전자 안내 |
| 아형 예측 | 26개 아형 중 상위 5개 확률 표시 |
| 확신 단계 | 높음·보통·낮음·판단 보류. 구간별 검증 적중률을 함께 표시 |
| 근거 표시 | 1순위 확률을 가장 많이 올린 변이 (예: `IDH1 R132H`) |

**화면에 넣은 모델**: 브라우저에서 돌아가야 해서 대회 제출 모델이 아닌 가벼운 로지스틱 회귀 하나를 넣었다(쌍 규칙 없음).

| 지표 (5겹 교차 검증) | 값 |
|---|---|
| Macro F1 | 0.419 |
| 1순위 적중률 | 41% |
| 상위 3개 안 적중률 | 68% |

| 확신 단계 | 1순위 확률 | 검증 적중률 | 전체 환자 중 비율 |
|---|---|---|---|
| 높음 | 60% 이상 | 76% | 19% |
| 보통 | 40~60% | 52% | 15% |
| 낮음 | 40% 미만 | 29% | 66% |

**오늘 화면을 고친 점**

1. **`TP53 R273C` 하나만 넣으니 백혈병(LAML)이 1순위로 나왔다.**
   - 원인 1: 이 변이를 가진 train 환자 92명은 15개 아형에 흩어져 있다.
   - 원인 2: 변이가 1개인 환자는 LAML·갑상선암·신장암에 많다. 그래서 모델이 "변이가 적다"는 패턴에 기댔다.
   - 조치: 변이가 1개이고 1순위 확률이 60% 미만이면 **판단 보류**로 표시한다. TP53·KRAS·PIK3CA·PTEN 단독 입력에는 경고 문구를 띄운다.
2. **train 파일을 통째로 넣으니 화면이 오른쪽으로 끝없이 늘어났다.** 팀원 피드백으로 발견했다.
   - 조치: 가로형 파일을 자동으로 인식해 **일괄 분석**으로 처리하고, 긴 문자열은 줄바꿈한다.
   - 주의: train으로 일괄 분석하면 Macro F1이 0.789로 나온다. 학습에 쓴 데이터라 부풀려진 값이고, 새 환자 기준 성능은 교차 검증 값 0.419다.

**화면에서 더 고칠 점**: final v6 EDA에서 KRAS, SMAD4, NRAS, GTF2I 열이 데이터에 없다는 것이 확인됐다. 화면 예시 중 '간 전이' 사례(KRAS, SMAD4 포함)는 두 유전자가 "학습에 없는 유전자"로 빠진다. 예시를 데이터에 있는 유전자로 바꾸고, 화면에 이 한계를 안내한다.

| 우선순위 | 가설 | 실험과 판정 |
|---|---|---|
| 1 | final v6에 v13의 반복 표기 정리와 희귀 유형 제외를 더하면 더 오른다 | 두 처리는 서로 다른 부분(반복 묶음, 집계 피처 폭주)을 고친다. final v6 파이프라인에 하나씩 더해 교차 검증과 바뀐 예측 수를 확인한다 |
| 2 | LightGBM 비중 35%가 final v6에서도 유리하다 | final v6 예측으로 20%, 35%, 50%를 그룹 3겹 검증으로 비교한다. 두 시드에서 모두 앞서야 채택한다 |
| 3 | 로그 평균은 한 모델이 낮게 본 클래스 확률을 크게 낮춘다 | 비중을 고정하고 로그 평균과 산술 평균을 비교한다. 전체 Macro F1과 소수 클래스 재현율을 본다 |
| 4 | 합성 변이의 학습 가중치를 낮추면 고변이 환자와 전체 성능의 균형이 좋아진다 | 증강 행 가중치만 0.25에서 0.10으로 바꾼다. 전체와 고변이 구간 Macro F1을 함께 본다 |
| 5 | 일부 frameshift 토큰이 `*`도 포함해 nonsense로 분류된다 | v10·v13 파서에서 fs와 `*`를 함께 가진 토큰 수를 센다. final v6의 HGVS 파서는 frameshift를 먼저 검사하므로 이미 해결됐는지도 확인한다 |
