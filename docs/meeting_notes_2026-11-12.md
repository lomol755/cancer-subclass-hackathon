**final v7에서 확인한 것**

- 제출 데이터에서 희귀 영향 제외 2,419칸, 반복 표기 정리 27,563칸이 바뀌었다. 학습 데이터는 각각 3칸, 0칸이었다.

- 해석: v6의 SKCM 예측이 모두 오류는 아니었다. 제출 데이터에 변이가 많은 환자가 많고 SKCM은 변이가 가장 많은 아형이다.
- 결론: LR·LightGBM 설정과 표기 처리 보강은 여기서 멈춘다.

### 3-4. 저녁 2: 솎아낸 검증과 v23

**솎아낸 검증**: 검증 폴드에서 변이 60개 이상 환자의 변이를 30~100개만 무작위로 남겨 평가한다(쌍 규칙 없음). 제출 데이터는 변이 30~100개 환자 비율이 학습 데이터보다 훨씬 높다(학습 16%, 제출 38%).

| 실험 | 일반 검증 | 솎아낸 검증 | 판정 |
|---|---|---|---|
| v14 | 0.5348 / 0.5264 | 0.2228 / 0.2169 | 기준 |
| v21 | 0.5600 / 0.5538 | 0.2638 / 0.2337 | 리더보드와 같은 방향(+0.041 / +0.017) |
| **v23: 치환 모델 솎아내기 증강 25%** | 0.56262 / 0.55239 | **0.2862 / 0.2839** | **내일 1순위 후보** |
| 솎아내기 증강 30% | 0.56628 / 0.55164 | 0.2871 / 0.2880 | 내일 2순위 후보 |
| 기본 모델(LR·LightGBM·스태킹)까지 솎아내기 | 0.5582 / 0.5476 | 0.2884 / 0.2803 | 기각 |
| 혼합 비중을 솎아낸 검증으로 선택 | 일반 검증 최대 −0.001 | +0.011 | 보류 (검증 과적합 우려) |

- 솎아내기 증강: 학습 폴드의 변이 60개 이상 환자마다 변이 일부만 남긴 복제본 2개를 비중 0.5로 치환 모델에 함께 학습한다. 제출 데이터는 쓰지 않는다.
- v23은 v21 대비 143행이 바뀌었고, 가장 큰 변화는 STES → COAD 23행이다. 실패한 통합 후보와 **반대 방향**이다.
- 기본 모델에 솎아내기가 통하지 않은 이유(추정): 기본 모델은 핵심 유전자를 보는데, 솎아내면 핵심 유전자가 빠져 잡음이 된다. 치환 모델은 변이 종류의 비율을 봐서 솎아내도 비율이 유지된다.
